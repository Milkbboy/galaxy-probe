# 아웃게임 화면 분리 및 굴착기 업그레이드 UI 개편 계획

> 작성: 2026-07-14  
> 대상: `Title.unity`의 `HubPanel`  
> 기준 이미지: 사용자가 제공한 `굴착기업그레이드.png` 콘셉트  
> 선행 기준점: 커밋 `a04ad54` (`타이틀 화면 하단 메뉴 UI 개편`)

## 0. 문서 목적

현재 하나의 `HubPanel`에 캐릭터 선택, 굴착기 강화, 무기 강화, 어빌리티, 보석 채집, 스탯이 동시에 노출되는 구조를 다음 3개 화면으로 분리한다.

1. **UPGRADES** — 굴착기 및 채집 계통 영구 강화
2. **CHARACTER** — 캐릭터 선택과 캐릭터별 고유 능력
3. **CRAFTING** — 무기 해금과 무기별 강화

1차 목표는 기능과 탐색 구조의 분리다. 이후 `UPGRADES` 화면을 기준 이미지처럼 **굴착기 프리뷰 + 업그레이드 트리 + 현재 능력치 + 구매 상세** 구조로 개편한다.

## 1. 핵심 결정

| 항목 | 결정 |
|---|---|
| 씬 구성 | 새 씬을 만들지 않고 기존 `Title.unity`의 `HubPanel`을 확장한다. |
| 공통 영역 | 상단 재화 표시와 하단 3개 내비게이션을 모든 아웃게임 화면에서 유지한다. |
| 화면 전환 | 패널을 새로 생성·파괴하지 않고 미리 만든 화면 루트를 `SetActive`로 전환한다. |
| 저장 데이터 | 기존 `UpgradeManager`, `WeaponUpgradeManager`, `DataManager` 저장 키와 레벨을 유지한다. |
| 구매 로직 | UI를 분리하되 실제 비용 확인·차감·레벨 증가는 기존 매니저가 계속 담당한다. |
| 해상도 | 1920×1080 기준으로 먼저 완성하고, Canvas Scaler 축소 환경을 추가 확인한다. |
| 폰트 | 코드로 생성하는 TMP에는 `TMPFontHelper.ApplyDefaultFont`로 D2Coding을 적용한다. |
| 구현 방식 | `BuildOnce + cached view + patch` 패턴을 유지해 입력 시 UI 흔들림을 막는다. |
| 레거시 처리 | 기존 통합형 `HubPanel`은 새 화면이 검증될 때까지 롤백 가능한 형태로 보존한다. |

### 이번 작업에서 하지 않는 것

- 인게임 전투·채굴 로직 변경
- 업그레이드 수치 또는 비용 밸런스 조정
- 플레이어 저장 데이터 초기화 또는 마이그레이션
- 업그레이드 트리 선행 조건을 임의로 추가
- 최종 굴착기 3D 모델·고급 애니메이션 제작

## 2. 현재 구조와 문제점

### 현재 진입 흐름

```text
TitleLandingPanel
├── UPGRADES  ─┐
├── CHARACTER ─┼─> 동일한 HubPanel 활성화
└── CRAFTING  ─┘      └─ HubController.Focus()가 대상 버튼만 선택
```

`TitleUI.ShowUpgradeHubPanel`, `ShowCharacterHubPanel`, `ShowCraftingHubPanel`은 서로 다른 `FocusTarget`을 전달하지만, `HubController`는 실제 화면을 나누지 않고 해당 서브패널의 첫 버튼에 포커스만 옮긴다.

### 현재 `HubPanel` 콘텐츠

| 현재 패널 | 담당 UI | 최종 소속 화면 |
|---|---|---|
| `CharacterSelectSubPanel` | `CharacterSelectUI` | CHARACTER |
| `ExcavatorUpgradeSubPanel` | `ExcavatorUpgradeUI` | UPGRADES |
| `GemUpgradeSubPanel` | `GemUpgradeUI` | UPGRADES |
| `WeaponShopSubPanel` | `WeaponShopUI` | CRAFTING |
| `AbilityShopSubPanel` | `AbilityShopUI` | CHARACTER |
| `StatDisplaySubPanel` | `StatDisplayUI` | 화면별 분리 또는 문맥별 재사용 |

### 해결할 문제

- 서로 관련 없는 정보가 한 화면에 보여 시선 흐름이 불명확하다.
- 타이틀 하단 메뉴가 화면 분류처럼 보이지만 실제로는 같은 화면을 연다.
- 굴착기 강화 항목이 작은 행 목록이라 핵심 성장 시스템의 존재감이 약하다.
- 3열 Masonry 레이아웃 때문에 한 시스템이 사용할 수 있는 폭이 제한된다.
- 화면별 제목·설명·선택 상태가 없어 사용자가 현재 위치를 파악하기 어렵다.

## 3. 목표 정보 구조

```text
HubPanel
├── CommonHeader
│   ├── BackButton
│   ├── ScreenTitle
│   └── CurrencyBar (Ore / Gem)
├── ScreenContainer
│   ├── UpgradeScreen
│   ├── CharacterScreen
│   └── CraftingScreen
└── BottomNavigation
    ├── UpgradesButton
    ├── CharacterButton
    └── CraftingButton
```

한 번에 `ScreenContainer`의 자식 하나만 활성화한다. 공통 헤더와 하단 내비게이션은 화면 전환 시 재생성하지 않는다.

### 3.1 UPGRADES 화면

기준 이미지의 구성을 현재 데이터에 맞게 다음처럼 변환한다.

```text
┌──────────────┬────────────────────────────┬──────────────┐
│ 강화 계통 목록 │ 굴착기 프리뷰 + 강화 트리      │ 현재 스탯     │
│ HP / 장갑     │ 선택 노드와 연결선             │ HP / 장갑     │
│ 채굴 속도     │ 현재 레벨·잠금·구매 가능 표시   │ 채굴 속도     │
│ 목표량        │                            │ 목표량        │
│ 보석 탐지     │                            │ 보석 획득 관련 │
│ 채집 속도     │                            │              │
├──────────────┴────────────────────────────┴──────────────┤
│ 선택 강화 설명 │ 현재 → 다음 레벨 │ 비용 │ UPGRADE 버튼      │
└──────────────────────────────────────────────────────────┘
```

#### 기존 데이터 매핑

| 화면 항목 | Upgrade ID | 타입 |
|---|---|---|
| 굴착기 내구도 | `excavator_hp` | `MaxHealth` |
| 장갑 강화 | `excavator_armor` | `Armor` |
| 채굴 속도 | `mine_speed` | `MiningRate` |
| 목표량 확장 | `mine_target` | `MiningTarget` |
| 보석 탐지 | `gem_drop` | `GemDropRate` |
| 채집 속도 | `gem_speed` | `GemCollectSpeed` |

초기 버전에서는 6개 항목을 독립 강화로 유지한다. 노드 연결선은 분류와 진행도를 보여주는 시각 요소로만 사용하며 실제 선행 조건을 뜻하지 않는다.

#### 트리 선행 조건을 도입할 경우

실제 잠금 관계가 필요해지면 `UpgradeData`에 다음 정보를 명시적으로 추가하는 별도 데이터 작업이 필요하다.

- 선행 업그레이드 ID
- 요구 선행 레벨
- 트리 좌표 또는 행/열
- 노드 분기 그룹

이 데이터가 확정되기 전에는 UI에서 가짜 잠금 조건을 만들지 않는다.

### 3.2 CHARACTER 화면

- 상단 또는 좌측: 캐릭터 3종 선택
- 중앙: 선택 캐릭터 프리뷰, 이름, 타이틀, 설명
- 우측: 현재 캐릭터 능력치
- 하단: 고유 어빌리티 3개, 해금 비용, 요구 어빌리티, 선택 상태
- 캐릭터를 변경하면 `AbilityShopUI`만 해당 캐릭터 데이터로 패치한다.

기존 `CharacterSelectUI`, `AbilityShopUI`, `CharacterRegistry`의 데이터 흐름을 유지한다.

### 3.3 CRAFTING 화면

- 좌측: 무기 5종 목록과 잠금 상태
- 중앙: 선택 무기 프리뷰와 설명
- 우측: 무기 현재 스탯
- 하단: 해당 무기의 강화 3종, 현재/다음 수치, 비용, 구매 버튼
- 기존 `WeaponShopUI`와 `WeaponUpgradeManager`를 재사용한다.

## 4. 화면 전환 설계

### 상태

```csharp
public enum HubScreen
{
    Upgrades,
    Character,
    Crafting
}
```

`FocusTarget`이 단순 포커스 이동을 담당하던 구조를 실제 화면 상태로 승격한다. 기존 호출부와의 호환이 필요하면 `FocusTarget`을 즉시 제거하지 않고 `HubScreen`으로 매핑한 뒤 단계적으로 정리한다.

### 전환 책임

`HubController` 또는 별도 `HubScreenController`가 다음을 담당한다.

1. 현재 화면 상태 저장
2. 대상 화면 루트만 활성화
3. 헤더 제목과 보조 문구 변경
4. 하단 메뉴 선택 비주얼 갱신
5. 첫 선택 가능 버튼으로 EventSystem 포커스 이동
6. 레이아웃을 다음 프레임에 leaf-first 방식으로 재계산
7. 옵션 화면에서 돌아올 때 마지막 화면 복원

### 기본 진입 규칙

| 진입 경로 | 첫 화면 |
|---|---|
| 타이틀 `UPGRADES` | `Upgrades` |
| 타이틀 `CHARACTER` | `Character` |
| 타이틀 `CRAFTING` | `Crafting` |
| 세션 결과의 `업그레이드 하기` | `Upgrades` |
| 옵션 닫기 | 옵션 진입 전 화면 |
| 화면 상태가 없거나 잘못됨 | `Upgrades` |

## 5. 단계별 구현 계획

## Phase 1 — 기능적 화면 분리

목표: 기존 UI를 재사용해 세 메뉴가 서로 다른 화면처럼 동작하게 한다.

- `HubScreen` 상태와 화면 전환 메서드 추가
- 기존 서브패널을 소속 화면별 루트로 묶거나 런타임에 그룹 제어
- `TitleUI`의 3개 진입 메서드를 실제 화면 전환에 연결
- 옵션 진입/복귀 시 마지막 화면 기억
- 비활성 컬럼이 폭을 차지하지 않도록 화면별 레이아웃 분리
- 키보드·게임패드 포커스가 숨겨진 버튼에 남지 않도록 정리

완료 기준:

- 타이틀 하단 3개 버튼이 각각 다른 콘텐츠만 표시한다.
- 화면 전환 후 다른 화면의 패널이 보이거나 공간을 차지하지 않는다.
- 기존 구매, 캐릭터 선택, 무기 해금이 모두 동작한다.

## Phase 2 — 공통 셸과 하단 내비게이션

목표: 세 화면에서 동일한 상단·하단 구조를 사용한다.

- 타이틀 화면에서 만든 금속형 하단 버튼 스타일 재사용
- `UPGRADES / CHARACTER / CRAFTING` 선택 상태 표현
- 공통 뒤로가기, 화면 제목, 재화 바 배치
- 개발용 치트·초기화 버튼은 릴리즈 빌드에서 숨김 유지
- 화면 전환 중 패널 생성·파괴 없이 활성 상태와 텍스트만 패치

완료 기준:

- 현재 화면 버튼이 색상·글로우로 명확히 구분된다.
- 어느 화면에서도 광석과 보석 값이 즉시 갱신된다.
- 뒤로가기는 타이틀 랜딩으로, 옵션 복귀는 기존 화면으로 돌아간다.

## Phase 3 — 굴착기 업그레이드 화면 기능 이관

목표: 기존 행 목록을 목업형 선택/상세/구매 흐름으로 바꾼다.

- 6개 강화 데이터를 선택 가능한 카테고리 또는 노드로 표시
- 선택된 강화의 이름·설명·현재 레벨·최대 레벨 표시
- 현재 값과 다음 레벨 값 계산 및 비교 표시
- 광석/보석 요구량과 보유량 표시
- 구매 가능, 재화 부족, 최대 레벨 상태 구분
- 구매 후 전체 재생성 없이 선택 노드와 관련 수치만 갱신
- 현재 굴착기 스탯을 `MachineData + UpgradeManager bonus`로 표시

완료 기준:

- 기존 6종 강화의 레벨과 비용이 이전 UI와 동일하다.
- 구매 후 재화, 레벨, 현재/다음 수치, 스탯이 같은 프레임에 갱신된다.
- 최대 레벨에서는 구매 버튼이 비활성화되고 완료 상태가 표시된다.

## Phase 4 — 굴착기 화면 비주얼 고도화

목표: 기준 이미지의 정보 밀도와 SF 산업 장비 분위기를 프로젝트 스타일로 재구성한다.

- 중앙 굴착기 프리뷰 이미지 또는 렌더 프리뷰 적용
- 육각 노드, 연결선, 잠금/완료/선택 상태 제작
- 선택 항목별 강조색과 중앙 프리뷰 포인트 연동
- 하단 상세 카드와 구매 버튼을 금속형 UI 스타일로 통일
- 1920×1080에서 텍스트와 클릭 영역 가독성 조정
- 이미지 에셋은 원본/생성본과 Unity 임포트본의 위치를 구분해 보관

완료 기준:

- 화면을 처음 봤을 때 굴착기 강화 화면임을 즉시 인지할 수 있다.
- 장식이 텍스트·비용·구매 버튼보다 강하게 보이지 않는다.
- 선택, 구매 가능, 재화 부족, 잠금, 완료 상태가 색상만이 아니라 형태로도 구분된다.

## Phase 5 — 캐릭터 전용 화면 재배치

- 캐릭터 선택 카드와 어빌리티 카드를 한 화면 흐름으로 재배치
- 선택 캐릭터 프리뷰와 테마 색상 적용
- 캐릭터 변경 시 어빌리티 3개와 스탯만 패치
- `CharacterSelectUI`의 첫 프레임 레이아웃 보정 유지
- 요구 어빌리티와 보석 비용 표시 검증

완료 기준:

- 굴착기 강화 항목이 CHARACTER 화면에 노출되지 않는다.
- 캐릭터 선택 직후 어빌리티와 설명이 겹치거나 한 프레임 흔들리지 않는다.

## Phase 6 — 무기 제작/강화 전용 화면 재배치

- 무기 목록, 선택 무기 프리뷰, 무기별 강화 행을 분리 배치
- 잠금/해금 상태 전환 시 해당 카드 본문만 교체
- 무기별 스탯과 강화 효과 계산 결과 표시
- 기존 2열 카드 구조를 전용 화면 폭에 맞게 단순화

완료 기준:

- 캐릭터·굴착기 강화가 CRAFTING 화면에 노출되지 않는다.
- 무기 해금과 강화 후 카드 전체가 흔들리지 않는다.

## Phase 7 — 통합 QA 및 문서 정리

- 모든 화면 진입 경로 확인
- 저장 후 재실행했을 때 선택 캐릭터·업그레이드·무기 상태 확인
- 1920×1080 및 축소 해상도 확인
- 마우스, 키보드, 게임패드 포커스 이동 확인
- 에디터 재생 진입/종료 반복 시 이벤트 중복 구독 확인
- `V2HubCanvasSetupEditor` 재실행 시 새 계층을 재현할 수 있는지 확인
- 완료 후 이 문서를 구현 결과와 실제 계층 기준으로 갱신

## 7. 데이터 및 저장 호환성

### 그대로 유지되는 항목

- `UpgradeManager`의 업그레이드 ID와 레벨
- `WeaponUpgradeManager`의 무기 강화 레벨
- `DataManager`의 광석, 보석, 선택 캐릭터, 무기 해금 상태
- `GameEvents`의 재화·구매·캐릭터 선택 이벤트
- Google Sheets → ScriptableObject 임포트 흐름

### 주의 사항

- UI에서 기본 스탯을 중복 합산하지 않는다.
- 강화 SO의 `BaseValue`는 캐릭터/머신 기본 수치가 아니라 강화 보너스 기준으로 취급한다.
- 비용과 구매 가능 여부를 UI에서 별도로 재구현하지 않고 매니저 결과를 사용한다.
- 화면 전환을 이유로 이벤트를 중복 구독하지 않는다.
- 새 트리 잠금 규칙을 도입할 때는 기존 저장 레벨이 잠긴 노드에 존재할 수 있는 경우를 정의해야 한다.

## 8. QA 체크리스트

### 화면 전환

- [ ] 세 타이틀 메뉴가 정확한 화면을 연다.
- [ ] 하단 메뉴로 세 화면을 왕복할 수 있다.
- [ ] 비활성 화면이 레이아웃 공간을 차지하지 않는다.
- [ ] 화면 전환 후 포커스가 숨겨진 오브젝트에 남지 않는다.
- [ ] 옵션 화면을 닫으면 이전 화면으로 돌아온다.
- [ ] 뒤로가기로 타이틀 랜딩 화면에 복귀한다.

### 굴착기 강화

- [ ] 6개 업그레이드가 모두 표시된다.
- [ ] 현재 레벨, 최대 레벨, 현재 효과, 다음 효과가 정확하다.
- [ ] 광석·보석 비용과 보유량이 정확하다.
- [ ] 구매 가능/재화 부족/완료 상태가 구분된다.
- [ ] 구매 후 저장하고 재실행해도 레벨이 유지된다.
- [ ] 현재 굴착기 스탯이 인게임 적용 수치와 일치한다.

### 캐릭터와 무기

- [ ] 선택 캐릭터와 어빌리티가 일치한다.
- [ ] 캐릭터 전환 시 카드 겹침이나 레이아웃 흔들림이 없다.
- [ ] 무기 잠금/해금과 강화 레벨이 기존 저장과 일치한다.
- [ ] 무기 구매 후 전체 카드가 재생성되지 않는다.

### 안정성

- [ ] Unity Console 컴파일 오류가 없다.
- [ ] Missing Script / Missing Sprite / Missing Font가 없다.
- [ ] 에디터 셋업 메뉴 재실행 후 동일한 화면이 재생성된다.
- [ ] 개발 빌드와 릴리즈 빌드에서 치트 버튼 노출 규칙이 유지된다.
- [ ] 1920×1080에서 텍스트 잘림과 클릭 영역 겹침이 없다.

## 9. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 현재 `Title.unity`와 셋업 에디터가 불일치 | 씬 직접 수정과 생성 코드 수정을 같은 Phase에서 함께 반영한다. |
| 중첩 LayoutGroup/ContentSizeFitter로 첫 프레임 크기 오류 | 화면 루트별 레이아웃을 단순화하고 leaf-first 리빌드 패턴을 제한적으로 사용한다. |
| 화면 전환마다 UI 재생성으로 흔들림 | `BuildOnce + cached views + patch` 원칙을 유지한다. |
| 목업의 무기 중심 정보가 굴착기 데이터와 혼동 | 목업의 배치 원칙만 차용하고 목록은 기존 굴착기/채집 6종으로 치환한다. |
| 트리 그래픽이 실제 선행 조건처럼 오해됨 | 데이터가 추가되기 전에는 연결선을 계통 분류 표현으로 명시한다. |
| 고해상도 이미지로 저장소 용량 증가 | 원본, Unity용 압축본, 문서용 이미지를 구분하고 중복 파일을 최소화한다. |
| 사용자 로컬의 패키지/프로젝트 설정 변경과 충돌 | Phase별 커밋에서 타이틀/허브 관련 파일만 명시적으로 스테이징한다. |

## 11. 최종 완료 정의

다음 조건을 모두 만족하면 전체 분리 작업을 완료로 본다.

1. 타이틀과 허브의 `UPGRADES / CHARACTER / CRAFTING`이 실제로 독립 화면을 연다.
2. 세 화면은 공통 헤더와 하단 내비게이션을 사용하며 현재 위치를 명확히 표시한다.
3. 굴착기 화면은 프리뷰, 강화 계통, 현재 스탯, 선택 상세, 비용, 구매 버튼을 한 화면에 제공한다.
4. 캐릭터 화면은 캐릭터 선택과 해당 캐릭터의 어빌리티만 보여준다.
5. 제작 화면은 무기 해금과 해당 무기의 강화만 보여준다.
6. 기존 재화, 업그레이드 레벨, 캐릭터 선택, 무기 해금 저장 데이터가 그대로 유지된다.
7. 화면 전환과 구매 과정에서 레이아웃 흔들림, 입력 포커스 유실, Missing 참조가 없다.
8. `V2HubCanvasSetupEditor`로 새 구조를 재현할 수 있고 관련 문서가 실제 구현과 일치한다.
